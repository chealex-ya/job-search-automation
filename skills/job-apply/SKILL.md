# Отклик на вакансию

Вход: ссылка на вакансию на сайте работодателя или описание вакансии текстом.

## 0. Источники фактов

- Факты о кандидате — из `memory/memory.md` (мастер-профиль: реквизиты, карьера, устойчивые формулировки, стоп-лист).
- Правила генерации — из `constraints.md`: никаких выдуманных фактов, усиления формулировок и абсолютных сумм.

Мини-контракт на случай, если файлы не найдены: факты брать только из переданных владельцем материалов; чего нет — ставить `<TODO: подтвердить: …>` и спрашивать, а не выдумывать; ничего не отправлять.

## 1. Забрать вакансию с сайта

WebFetch и браузерные прокси с карьерных сайтов российских компаний часто не работают: сертификаты не проходят проверку, контент рендерится JS. Рабочий способ — curl с `-sk`:

```
curl -skL --compressed -A "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/126.0.0.0 Safari/537.36" "<url>" -o _tmp_vac.html
```

Если сайт собран на Next.js (частый случай), внутри страницы есть `<script id="__NEXT_DATA__" type="application/json">` — python'ом выдернуть JSON, найти ветку с данными вакансии (обычно `props.pageProps.…`) и сохранить в `vacancy.json` (`ensure_ascii=False, indent=2`). Кириллицу в консоль не выводить (ломается кодировкой на Windows) — писать в файл и читать его.

Ключевые поля искать по смыслу: название, обязанности, требования, условия, контакт рекрутера, тип занятости, требуемый опыт.

Если сайт не Next.js и разобрать не удалось — попросите владельца скопировать текст вакансии и сохраните его в `vacancy.json` вручную структурированным. Выдумывать содержимое вакансии нельзя.

## 2. Папка и файлы

В рабочем каталоге создать подпапку с именем вакансии. Если имя уже занято — добавить порядковый номер или специфику. Внутри ровно три файла:

- `Резюме — <Имя Фамилия>.html` — адаптированное резюме
- `Follow-up письмо — <Имя Отчество рекрутера>.md` — письмо рекрутеру на почту
- `vacancy.json` — исходник вакансии

Письмо для отклика на сайте НЕ делать — владелец откликается на сайте сам (если не сказано иное).

## 3. Резюме

База: путь из памяти (раздел «Реквизиты»). Практичнее взять копию последнего резюме из соседней папки вакансии (актуальная вёрстка и правила уже применены) и адаптировать под новую вакансию.

### Общие правила вёрстки

- Секция называется **Summary**: 3–5 предложений, начинается с роли, без размера команды, факты под вакансию.
- Шапка места работы двухстрочная: строка 1 — компания (акцентным цветом) + даты справа; строка 2 — должность. Без города у позиций.
- Ранний опыт — один компактный блок «Ранее · <годы>» в конце опыта, без отдельных описаний.
- HTML под печать: `@page { size: A4; ... }`, PDF — через Ctrl+P из браузера.
- Контакты в шапке — из памяти, везде одинаковые.

### Правила стиля владельца

Устойчивые формулировки и стоп-лист — из памяти (соответствующие разделы). Не перефразировать устойчивое, не пропускать стоп-лист.

### Адаптация под тип вакансии

- Бизнесовые вакансии: убрать технику (API/REST/JSON, архитектуру, промпт-инжиниринг), оставить инструменты уровня продуктовой аналитики (SQL акцентировать).
- Технические/рисковые вакансии: наоборот, добавить соответствующие факты (безопасность, регуляторика, интеграции) — из памяти, не из воображения.

## 4. Follow-up письмо

Рекрутер и почта — из `vacancy.json` (контактные поля). Первый абзац снимает «паспортный» вопрос: кто я, на какую вакансию откликнулся, зачем пишу напрямую.

```
Добрый день, <имя>!

Меня зовут <Имя Фамилия>. Я откликнулся на вакансию «<название>» (<краткая специфика>) на сайте компании и хочу напрямую подтвердить свою заинтересованность, позиция очень близка моему опыту.

- <буллет 1: текущая роль, релевантная вакансии>
- <буллет 2–3: релевантные факты из прошлого>
- <буллет: команды / data-driven: метрики, эксперименты, инструменты>

Резюме прикладываю к письму, отклик на сайте уже оставил. Буду рад короткому созвону.

С уважением,
<Имя Фамилия>

<телефон> · Telegram: <ник> · <email>
```

Правила: 3–4 буллета через дефис `-`, по одному на строку; без заголовков и тире-эмдаш; без кода вакансии в теле; объём 150–200 слов; тема письма — короткая, по делу; вложение — резюме PDF. Одна сильная связка метрик, без абсолютных сумм.

## 5. Чек-лист перед сдачей

- Реквизиты из памяти использованы везде, почта единая
- Summary, двухстрочные шапки, блок «Ранее»
- Нет формулировок из стоп-списка; устойчивые формулировки на месте
- Резюме адаптировано под тип вакансии (бизнес/техника)
- В письме: имя рекрутера, стиль буллетов, подпись с контактами
- Каждый факт трассируется до памяти; `<TODO>`-заглушки перечислены владельцу явно
